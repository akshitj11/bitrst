## Mempool

`Mempool` validates non-coinbase transactions against the active UTXO set and in-pool spends. Capacity is bounded by tx count and serialized bytes. When full, the lowest fee-rate transaction is evicted first. `MempoolHandle` exposes the pool to concurrent peer tasks.

Reorgs call `apply_chain_events` or `synchronize_to_chain`. Confirmed transactions drop out. Transactions from disconnected blocks return when the heavier fork wins, using the disconnected-block journal for exact replay.

## FileBlockStore

`FileBlockStore` persists blocks as one lowercase hex file per hash. Writes go through a same-directory `.tmp` file, `fsync`, and `rename`. Opening the store removes stale temp files and invalid filenames. The CLI still uses ephemeral in-memory chains; persistence is for library callers and tests.

## Failure modes we hit

**Event cursor lag.** Peers that stop draining `ChainEvent` logs fall behind the bounded journal. Mempool state diverges until `sync_mempool` replays from a `ChainEventCursor`. Fix: non-destructive cursor API and explicit resync on relay.

**Disconnect journal overrun.** If mempool resync needs a block older than the retained disconnect window, recovery returns `DisconnectedBlockRecoveryError`. The journal capacity must cover the event journal window.

**MTP equals block time.** CLI `mine` with `--network-time` equal to genesis time fails timestamp validation because the first mined block must be strictly above median past time. Use a network time at least one second above genesis, or omit `--time` and let the CLI pick a valid base.

**Checksum mismatch on the wire.** Integration tests reject corrupted message headers before they reach relay logic.

**Mempool serve without revalidation.** Serving a `getdata` tx directly from the pool could return a transaction that no longer validates after a reorg. Relay now revalidates before reply.

**FileBlockStore residue.** Interrupted writes and stray files in the store directory are cleaned on open so `get_block` does not trip over garbage.
